# Zialy Urpaq мектебі — учебная платформа

Платформа для заданий, тестирования и проверки ученических работ. Ученики могут войти по коду школы либо открыть отдельную страницу `/room` и подключиться к конкретной комнате теста по её шестизначному коду и ФИО. Администратор создаёт личные аккаунты сотрудников; учителя и администратор входят по email и паролю.

## Стек
- Web: Next.js 15, React 19, TypeScript
- API: NestJS 11, TypeScript
- Database: PostgreSQL 17
- ORM: Prisma 6

## Для школы

Сотруднику, который настраивает сервер, достаточно запустить файл `ZailyUrpaqSetup.exe` и заполнить поля в графическом окне: установщик сам проверит Docker, при необходимости скачает и установит Docker Desktop, развернёт платформу, создаст первого администратора и покажет адрес для входа. PowerShell-консоль не открывается. Требуются Windows 10 22H2 (19045) или Windows 11 23H2 (22631+) x64, аппаратная виртуализация, WSL 2.1.5+ и минимум 8 ГБ RAM; при первом запуске Docker попросит принять лицензию, а Windows иногда требует перезагрузку для включения WSL 2. Подробности для учителей и администратора школы — в [`инструкции на русском`](packaging/windows/README.md).

## Для разработки
- Windows, Node.js 22 LTS и npm 10+
- Docker Desktop с Compose

## Передача школе на одном компьютере

Для школьного сервера подготовлен Windows-установщик: инструкции находятся в [`packaging/windows/README.md`](packaging/windows/README.md). Он разворачивает приложение и PostgreSQL в Docker, создаёт первого администратора и показывает локальный адрес для входа с устройств школы. Исходник установщика собирается командой `.\packaging\windows\Build-Installer.ps1` в PowerShell Windows.

Внешний доступ через Cloudflare Tunnel необязателен. Адрес сайта и токен Cloudflare настраиваются в аккаунте самой школы; секреты не включаются в пакет и не сохраняются в GitHub.

Трансляция экрана в комнатах использует отдельный LiveKit WebRTC-сервис. Для неё нужен HTTPS-адрес сайта, случайные `LIVEKIT_API_KEY`/`LIVEKIT_API_SECRET`, публичный клиентский адрес `LIVEKIT_PUBLIC_URL` и статический LAN IPv4 сервера в `LIVEKIT_NODE_IP`. После настройки сервис запускается профилем Compose `media`; Caddy передаёт WebSocket-сигнализацию, а сеть школы должна пропускать WebRTC через TCP 7881 и UDP 7882. Cloudflare Tunnel передаёт сайт и сигнализацию, но не заменяет ICE/TURN-маршрут медиапотоков. Возможность захвата экрана зависит от мобильного браузера: API браузера требует HTTPS и не поддерживается одинаково на всех телефонах.

## Запуск в Windows PowerShell

```powershell
# 1. Перейти в каталог проекта
cd school-crm

# 2. Создать локальную конфигурацию
Copy-Item .env.example .env

# 3. Установить зависимости
npm install

# 4. Запустить PostgreSQL
 docker compose up -d postgres

# 5. Сгенерировать Prisma Client
npm run db:generate

# 6. Создать и применить миграцию
npm run db:migrate -- --name init

# 7. Запустить frontend и backend в двух процессах
npm run dev
```

Откройте http://localhost:3100. Веб-приложение использует порт 3100, чтобы не конфликтовать с другим локальным сайтом на 3000. Проверка API: http://localhost:4000/api/health. Успешный ответ должен содержать `status: "ok"` и `database: "connected"`.

## Важные замечания
- До публичного развёртывания замените секреты и пароль базы, ограничьте CORS и настройте HTTPS.
- Не храните загруженные файлы в публичной папке. Для production потребуется приватное хранилище, лимиты размера, проверка MIME-типа и авторизованная выдача файлов.
- Перед запуском убедитесь, что локальный порт 5432 свободен.
- `DATABASE_URL` в `.env` должна соответствовать паролю, указанному в `docker-compose.yml`.

## Модель данных
Схема включает пользователей и роли, классы, предметы, назначения преподавателей, задания, вопросы и варианты ответов, попытки учеников, ответы, вложения, историю оценок, уведомления и аудит.


## Тесты, учётные записи и результаты

Завершённые и проверенные попытки также попадают в отдельную PostgreSQL-базу `schoolresults`. Перенос выполняется фоновой очередью: временная недоступность базы результатов не отменяет тест ученика; доставка повторяется автоматически, а повторная запись обновляет запись по исходной попытке. Для Compose база запускается отдельным контейнером и отдельным томом `results_data`. Экспорт SQLite из интерфейса остаётся отдельным способом скачать снимок результатов. API health endpoint `GET /api/health` также сообщает состояние доставки в поле `resultsDelivery`: `connected`, `pending`, `unavailable` или `disabled`, а также количество незавершённых записей очереди, когда основная база доступна. Недоступность базы результатов не останавливает попытки учеников, но администратору следует проверить этот статус и логи сервера, если очередь долго не уменьшается.

### Вход и роли

Администратор создаёт аккаунты преподавателей в интерфейсе. Ученикам аккаунты не нужны: они входят по коду школы, имени и фамилии.

### Применение обновления схемы

После установки зависимостей из корня проекта выполните:

```powershell
npx prisma generate
npx prisma migrate dev
```

Затем перезапустите API и веб-приложение командой `npm run dev`.

### Основные API-маршруты

- `POST /api/auth/login` — вход преподавателя и администратора по email и паролю.
- `POST /api/auth/student-access` — вход ученика по общему коду, имени и фамилии.
- `GET /api/auth/users` и `POST /api/auth/users` — список и создание аккаунтов сотрудников для администратора.
- `GET /api/dashboard` — счётчики для панели преподавателя.
- `GET /api/assignments`, `POST /api/assignments` — список и создание задания.
- `PATCH /api/assignments/:id/publish` — публикация задания.
- `GET /api/assignments/:id/results` — все попытки, ФИО, время, ответы и баллы.
- `GET /api/rooms/:roomId/analytics` — сводка завершённых попыток комнаты: средний балл/процент, медианное время, точность и число ошибок по каждому вопросу, а также топ учеников. Доступна только админу и владельцу комнаты-преподавателю.
- `GET /api/student/assignments` — опубликованные задания для учеников.
- `GET /api/student/results` — личная история отправленных попыток, оценок и общего отзыва преподавателя.
- `GET /api/student/submissions/:submissionId/result` — результат собственной попытки, баллы по вопросам и комментарии преподавателя; правильные варианты и ключи проверки не раскрываются.
- `POST /api/student/assignments/:id/start` — начало попытки ученика, вошедшего по общему коду.
- `POST /api/student/assignments/:id/submissions/:submissionId/submit` — отправка ответов.
- `PATCH /api/submissions/:id/grade` — сохранение ручной оценки.

### Комнаты тестов

Опубликованное задание можно запускать в отдельных комнатах. Для каждой комнаты создаётся собственный шестизначный код и список участников; ученики подключаются на странице `/room`. Учитель управляет только комнатами, которые создал сам; администратор видит все комнаты. При старте комнаты вопросы фиксируются снимком, а правильные варианты не отправляются в браузер ученика. Для сетевого восстановления используется отдельный случайный токен комнаты, в базе хранится только его SHA-256-хэш.

- `POST /api/assignments/:assignmentId/rooms` — создать комнату.
- `GET /api/assignments/:assignmentId/rooms` и `GET /api/rooms/:roomId` — список и состав комнаты для сотрудника.
- `POST /api/rooms/:roomId/start` — начать тест до заполнения лобби.
- `POST /api/student/rooms/join-v2` — присоединиться по коду комнаты, имени и фамилии.
- `POST /api/student/rooms/:roomId/v2/proctor-events` — отправить событие ухода со страницы или возвращения в тест. Непрерывный эпизод учитывается один раз; на третьем эпизоде сервер завершает попытку по сохранённым ответам и сохраняет причину в `finishReason`.
- `GET /api/student/rooms/:roomId/v2` — восстановить свою сессию по токену комнаты.
- `PATCH /api/student/rooms/:roomId/v2/answers` — автоматически сохранить ответы.
- `POST /api/student/rooms/:roomId/v2/submit` — завершить попытку и получить результат с местом в комнате.

Для локального обновления существующей базы сначала сделайте резервную копию, затем примените миграцию и пересоздайте Prisma Client:

```powershell
npx prisma migrate deploy
npx prisma generate
```

Миграция добавляет таблицы комнат и участника и связывает старые попытки с архивными комнатами; она не удаляет задания, попытки или ответы. Перед применением на школьной базе проверьте резервную копию на отдельной тестовой БД.

### Границы текущей реализации

Автоматически проверяются одиночный выбор, множественный выбор и числовой ответ. Текстовые ответы отображаются в результатах и требуют ручной проверки. Сопоставление, заполнение пропусков и загрузка файлов пока не имеют полноценного пользовательского интерфейса или автоматической проверки.

Для учеников попытки учитываются по введённым имени и фамилии; ограничение числа попыток настраивается в задании.
