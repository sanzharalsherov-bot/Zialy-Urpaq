# AGENTS.md — Zialy Urpaq

## 1. Основные правила
- Сначала изучай существующий код, структуру проекта и документацию.
- Не переписывай проект с нуля, если задача этого не требует.
- Не удаляй работающий функционал и не меняй дизайн без необходимости.
- Реализуй реальный функционал, не подменяй его заглушками и демоданными.
- Если требования неоднозначны, уточни важные детали до рискованных изменений.
- Объясняй пользователю, что изменено, что проверено и что осталось сделать.

## 2. Технологии проекта
- Monorepo на npm workspaces.
- API: NestJS.
- Web: Next.js.
- База данных: PostgreSQL.
- ORM: Prisma.
- Учитывай существующие версии зависимостей и принятые в проекте соглашения.

Не меняй архитектуру, стек или основные зависимости без веской причины и согласования.

## 3. Безопасность
- Никогда не добавляй в Git пароли, токены, API-ключи, секреты и содержимое .env.
- Не ослабляй авторизацию, проверку ролей, валидацию или контроль доступа ради удобства.
- Проверяй права ADMIN, TEACHER и STUDENT на сервере, а не только в интерфейсе.
- Не раскрывай данные одного ученика другим пользователям без соответствующих прав.
- Не выполняй разрушительные операции с базой данных без предварительного согласования.
- Используй переменные окружения и безопасные примеры конфигурации.

## 4. Работа с базой данных
- Перед изменением схемы изучай существующую Prisma schema и миграции.
- Для изменений схемы создавай корректные миграции.
- Не удаляй существующие данные и миграции без согласования.
- Учитывай целостность данных и обратную совместимость.

## 5. Правила разработки
- Перед изменениями определи затрагиваемые файлы и возможные побочные эффекты.
- Делай небольшие, логически связанные изменения.
- Соблюдай существующий стиль кода.
- Не добавляй зависимости, если можно обойтись текущими инструментами.
- Не маскируй ошибки пустыми обработчиками и фиктивными ответами.
- Не утверждай, что функция работает, если она не была проверена.

## 6. Проверка результата
- Запускай подходящие проверки после изменений: сборку, тесты, линтер и проверки типов, если они настроены.
- Проверяй изменения на регрессии и проблемы безопасности.
- Если проверка не запущена или завершилась ошибкой, сообщай об этом явно.
- Не исправляй несвязанные с задачей проблемы без необходимости.

## 7. Git и GitHub
- Текущая рабочая ветка разработки: dev.
- Основная ветка: master.
- Новые задачи выполняй в рабочей ветке, если пользователь не указал другое.
- Не переключай ветки с незакоммиченными изменениями без проверки их состояния.
- Не выполняй push, merge, rebase, reset --hard или удаление веток без явного разрешения пользователя.
- Перед завершением проверяй git diff и git status.
- Не считай наличие Ruleset гарантией защиты, если GitHub сообщает, что правила не применяются.

## 8. Формат завершения задачи
В конце кратко укажи:
1. Что реализовано.
2. Какие файлы изменены.
3. Какие проверки выполнены и каков результат.
4. Какие ограничения или нерешённые проблемы остались.
