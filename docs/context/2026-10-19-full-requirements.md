Ты продолжаешь существующий проект Zaily Urpaq — локальную школьную платформу компьютерного тестирования с мониторингом учеников.

## 1. Конечная цель

Создать полностью работоспособную школьную систему тестирования, которую IT-специалист сможет установить на Windows 10/11 и запустить через графический лаунчер.

Учитель должен создавать тесты, запускать отдельные комнаты, контролировать прохождение, наблюдать за экранами учеников, получать результаты, рейтинг и аналитику.

Ученик должен подключаться по шестизначному коду комнаты, проходить тест с таймером и автосохранением, получать результат после завершения.

Система должна работать в локальной сети школы **без обязательного интернета, публичного домена и Cloudflare**.

## 2. Масштабирование и комнаты

- Один тест может использоваться в нескольких независимых комнатах.
- Каждая комната получает собственный шестизначный цифровой код.
- В комнате обычно 30–40 учеников.
- Поддерживать до 10 одновременных комнат и 300–400 учеников при условии подтверждения нагрузочными испытаниями.
- У каждой комнаты отдельные участники, таймер, статус, результаты и рейтинг.
- Учитель видит только свои комнаты; администратор может управлять всеми.
- Учитель может запустить комнату, даже если зарегистрировались не все ученики.
- После старта новые участники не допускаются; восстановление существующей сессии выполняется по действительному токену.
- Одинаковые ФИО не должны смешивать результаты учеников.
- Повторная попытка разрешается преподавателем индивидуально.

## 3. Создание тестов

Должно быть два способа создания тестов:

**Ручное создание:** преподаватель добавляет вопросы, варианты ответов, правильные ответы и баллы.

**Импорт из Word:** преподаватель скачивает шаблон DOCX, заполняет его и загружает в систему.

Поддерживаемые типы:
- Один правильный ответ.
- Несколько правильных ответов.

Для вопросов с несколькими правильными ответами балл начисляется только при полном совпадении множества выбранных вариантов с правильным. Частичные ответы не оцениваются положительно. Отрицательных баллов нет.

Каждый вопрос может иметь индивидуальный вес. Перед стартом комнаты необходимо фиксировать неизменяемый снимок вопросов, вариантов и правильных ответов.

Вопросы и варианты перемешиваются отдельно для каждого ученика; установленный порядок сохраняется для восстановления сессии.

## 4. Прохождение тестирования

- Вход по коду комнаты, имени и фамилии без регистрации аккаунта.
- Лобби ожидания до старта.
- Настраиваемый серверный таймер.
- Автосохранение каждого ответа.
- Локальные черновики во время кратковременного обрыва сети.
- Восстановление ответов после перезагрузки страницы.
- Таймер продолжает идти при отключении Wi-Fi.
- Автоматическое завершение после окончания времени.
- Преподаватель может завершить одну попытку или всю комнату.
- Повторное завершение не должно менять ранее рассчитанный результат.
- Результаты сохраняются даже при принудительном завершении.

Ученик не должен получать правильные ответы из API до завершения теста или через экран результатов.

## 5. Рейтинг и аналитика

Рейтинг формируется по правилам:

1. Больше набранных баллов.
2. Меньше нарушений.
3. Меньше времени прохождения.

В рейтинге учитывается последняя завершённая попытка, история предыдущих попыток сохраняется.

После тестирования ученик видит баллы, процент, затраченное время, место и рейтинг.

Преподаватель видит:
- Количество участников.
- Прогресс каждого ученика.
- Правильные, неправильные и пропущенные ответы.
- Статистику ошибок по вопросам.
- Распределение выбранных вариантов.
- Время ответа, если такая метрика достоверно сохранена.
- Рейтинг и результаты комнаты.
- Историю нарушений.
- Статус экспорта результатов.

## 6. Античит и контроль нарушений

В режиме строгого тестирования уход на другую вкладку или приложение, скрытие страницы и сворачивание окна должны регистрироваться как нарушение настолько надёжно, насколько это допускает браузер.

- Один непрерывный эпизод ухода — одно нарушение.
- После третьего нарушения попытка автоматически завершается.
- Уже сохранённые ответы оцениваются и остаются в рейтинге.
- F5, восстановление соединения и обычный кратковременный сетевой сбой не должны автоматически считаться списыванием.
- Учитель получает информацию о нарушениях.
- Не показывать преподавателю выбранные ответы в режиме реального времени.
- Три ошибочных ввода кода комнаты с одного IP и устройства — временная блокировка на 15 минут с журналированием.

Не заявлять абсолютную защиту: браузер не всегда может достоверно различить закрытие вкладки и перезагрузку, а также не контролирует все действия вне браузера.

## 7. Трансляция экранов через LiveKit

Реализовать мониторинг экранов через WebRTC/LiveKit.

Ученик на компьютере предоставляет браузеру разрешение на демонстрацию экрана.

Учитель должен видеть:
- Все 30–40 экранов своей комнаты.
- ФИО ученика.
- Статус подключения.
- Прогресс.
- Количество предупреждений.
- Увеличение выбранного экрана.
- Остальные экраны в виде миниатюр.

Требования безопасности:
- Ученик не может смотреть экраны других учеников.
- Преподаватель не может просматривать чужую комнату.
- Токены доступа ограничены конкретной комнатой и ролью.
- Завершённые попытки отключаются от медиасессии.
- Подписанные LiveKit-вебхуки проверяются сервером.
- Не считать успешный WebSocket 101 доказательством передачи видео.

На смартфонах поддержка захвата экрана зависит от браузера и ОС. Проверить реальные устройства; неподдерживаемые возможности явно фиксировать, не обещать их работу без испытаний.

## 8. Локальная школьная сеть

Это окончательно выбранная схема текущего развёртывания:

**Школьный сервер:** `192.168.10.8`

Другой проект на этом же компьютере уже работает в школьной сети.

Строго запрещено нарушать его работу.

Требования:
- Не занимать порт 3000 на Windows-хосте.
- Производственный сайт Zaily Urpaq — отдельный порт, плановый HTTP 8080.
- HTTPS через Caddy с `tls internal`.
- LiveKit — отдельные WSS, TCP и UDP.
- Изолированные Docker Compose-проекты и тома.
- Отдельная конфигурация и сертификаты.
- Не изменять чужие контейнеры, базы или службы.
- Установить постоянный адрес сервера через DHCP-резервирование или другое управляемое сетевое решение.

Временный проверочный стенд сейчас использует:
- HTTP 18080.
- HTTPS 18443.
- LiveKit TCP 7881.
- LiveKit UDP 7882.

Эти порты не обязательно являются окончательными.

Текущая незавершённая задача: исправить `SCHOOL_LAN_IP=127.0.0.1` в тестовом Caddy на действительный школьный IP `192.168.10.8`, правильно выпустить сертификат и проверить доверие, HTTPS, WSS и реальный WebRTC между устройствами.

## 9. Базы данных

Используются две отдельные PostgreSQL:

**Основная база:** пользователи, преподаватели, тесты, комнаты, участники, попытки, ответы, журналы событий.

**База результатов:** экспортированные результаты и аналитические представления.

Экспорт должен работать через устойчивую очередь с повторными попытками, не терять данные при недоступности второй базы и не создавать дубликаты при повторной отправке.

Перед изменениями схемы требуется проверенная резервная копия. Нельзя удалять существующие Docker volumes или изменять действующие данные ради тестирования.
